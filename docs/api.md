# API — lookups from scripts and integrations

IntelChecker's backend is a JSON API. Everything the UI does goes through it, and scripts, SOAR playbooks or SIEM enrichments can use it directly with an **API token**.

- Base URL: `http://<host>:<FRONTEND_PORT>/api` (through the frontend's nginx proxy), or `http://<host>:<BACKEND_PORT>` straight to the backend.
- Interactive reference of every endpoint (generated by FastAPI): `http://<host>:<BACKEND_PORT>/docs`.

---

## 1. Authentication

Every call needs credentials. For integrations, use an API token:

```
Authorization: Bearer ick_…
```

**Getting a token.** An admin creates it on the **Users** page: open the user's key button (it shows how many active tokens they have), give the token a name (e.g. *SOAR playbook*) and an expiry (30 / 90 / 365 days or never), and **copy the token right away — it is shown only once**. Only its hash is stored.

**What a token can do.** Exactly what its user can do, with the user's *current* role:

| Role of the token's user | `POST /lookup` · `/analyze/*` | `GET /history*` | `/users*` · `PUT /weights` |
|---|:-:|:-:|:-:|
| Admin | ✅ | ✅ | ✅ |
| Analyst | ✅ | ✅ | — |
| Reader | — | ✅ | — |

Tip: create a dedicated **Analyst** user per integration (e.g. `svc-soar`) and give it the token. Its lookups then show up in History under that name, and revoking access is one click.

**When a token stops working** (401 `InvalidToken`): it was revoked, it expired, or its user was disabled or deleted. Changing the user's role applies to the token at once; resetting the user's password does **not** revoke tokens (revoke them explicitly). A token can't change the user's password.

Browsers can also use the session cookie from `POST /auth/login`, which is what the UI does; tokens are the way for anything non-interactive.

## 2. `POST /lookup` — full lookup with verdict

Queries every configured source for the type in parallel, computes the verdict with the current Admin weights — the **same engine as the UI**, so scores match the results page — and stores the lookup in History under the token's user (marked **API**).

Request body:

| Field | Type | Default | Meaning |
|---|---|---|---|
| `indicator` | string | — | The IoC. Leading/trailing spaces are trimmed. |
| `type` | string | — | `ip`, `domain`, `url`, `hash`, `asn` or `threat-actor`. |
| `engines` | string[] | all | Only query these sources (ids as in `GET /engines/status`). |
| `exclude` | string[] | `[]` | Skip these sources. |
| `save` | bool | `true` | Store in History. `false` = just answer. |
| `include_raw` | bool | `false` | Add each source's raw response (`sources.<id>.data`). Can be large. |

Sources without their API key are never queried (same as the UI). The call returns when the slowest source answers or times out (~15–20 s at most).

```bash
TOKEN=ick_...
curl -s -X POST http://intelchecker.local:8080/api/lookup \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"indicator": "185.220.101.1", "type": "ip"}'
```

Response:

```json
{
  "history_id": 128,
  "indicator": "185.220.101.1",
  "type": "ip",
  "risk": 8,
  "knowledge": 10,
  "quadrant": "confirmed_malicious",
  "thresholds": { "knowledge": 4, "risk": 5 },
  "responded": 9,
  "queried": 10,
  "sources": {
    "virustotal": { "label": "VirusTotal", "outcome": "hit", "subscore": 10, "depth": 1, "error": null },
    "abuseipdb":  { "label": "AbuseIPDB",  "outcome": "hit", "subscore": 10, "depth": 1, "error": null },
    "greynoise":  { "label": "GreyNoise",  "outcome": "excluded", "subscore": null, "depth": null,
                    "error": { "code": "RateLimitExceeded", "message": "GreyNoise rate limit exceeded…" } }
  },
  "contributions": { "risk": [ … ], "knowledge": [ … ], "knowledgeFullAt": 70 }
}
```

- `risk` / `knowledge` — 0–10. `risk` is `null` when no source issued a verdict ("No data", never a clean 0). Both are `null`-safe to store.
- `quadrant` — `confirmed_malicious`, `isolated_signal`, `known_benign`, `known_low_signals`, `known_no_verdict` or `unknown` (meaning in [user-guide.md § 2](user-guide.md#2-the-two-scores)); `null` if no source answered.
- `sources.<id>.outcome` — `hit` (risk signal), `clean` (explicit benign verdict), `context` (has a record, no verdict), `no_data` (no record) or `excluded` (failed — see `error`).
- `contributions` — what each source added to each score; the same data the results page's **View matrix** and **How is this calculated?** use.
- `history_id` — open it in the UI at `/history/<id>`; `null` with `save: false`.

## 3. Other endpoints

| Endpoint | Needs | Returns |
|---|---|---|
| `GET /engines/status` | any | Every source: `connected` (has its key), supported `types`, label for MISP instances. |
| `POST /analyze/{engine}` `{indicator, type}` | analyst | One source's raw response, no verdict, not saved. |
| `GET /history[?indicator=…]` | reader | Latest 200 lookups (all of them for one indicator): scores, quadrant, `username`, `via` (`ui` / `api`). |
| `GET /history/{id}` | reader | One lookup with every source's stored response and contributions. |
| `GET /history/frequency?indicator=…` | reader | Times looked up in the last 24 h / 72 h / 30 d. |
| `GET /weights` | any | Current weights and thresholds. |
| `GET /auth/me` | any | The user behind the token/session and their permissions. |
| `GET /connectors` | admin | API keys (status, source `ui`/`env`, last 4 chars — never the key), MISP instances, files in `backend/certs/`. |
| `PUT` / `DELETE /connectors/keys/{ENV_NAME}` `{value}` | admin | Save / remove a source's key (e.g. `VIRUSTOTAL_API_KEY`). |
| `POST /connectors/misp` · `PATCH` / `DELETE /connectors/misp/{id}` | admin | Add / edit / delete a MISP instance (`name`, `url`, `key`, `verify_ssl`, `client_cert`, `client_key`; omit `key` on edit to keep it). |
| `POST /connectors/test/{engine}` | admin | One real lookup of a harmless indicator: `{ok, error}`. Uses one request of the source's quota. |

Errors are JSON: `{"detail": {"code": "…", "message": "…"}}` — `401 InvalidToken`/`NotAuthenticated`, `403 Forbidden` (role), `422 InvalidType`/`UnknownEngine`/`InvalidIndicator`.

## 4. Python example

```python
import httpx

API = "http://intelchecker.local:8080/api"
HEADERS = {"Authorization": "Bearer ick_..."}

def lookup(indicator: str, type_: str) -> dict:
    r = httpx.post(f"{API}/lookup", headers=HEADERS, json={"indicator": indicator, "type": type_}, timeout=60)
    r.raise_for_status()
    return r.json()

v = lookup("185.220.101.1", "ip")
if v["quadrant"] in ("confirmed_malicious", "isolated_signal"):
    flagged = [s["label"] for s in v["sources"].values() if s["outcome"] == "hit"]
    print(f"Block: risk {v['risk']}/10, knowledge {v['knowledge']}/10 — flagged by {', '.join(flagged)}")
```
